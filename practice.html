종이 활동지의 ①~⑧을 그대로 옮겨 적어요

활동지 3번 칸에 쓴 내용을 번호에 맞춰 적어요. 칸 아래의 확인 문장이 초록색이면 제미나이가 알아듣기 좋은 문장이에요.

내 발명품 [A]

쓴 내용은 이 컴퓨터에만 저장돼요
0 / 8

프롬프트에는 이름·학번 같은 개인정보를 쓰지 않아요. 발명품 이야기만 적어요.

[A] 내 발명품 + [B] 제작 규칙을 한 번에 복사해요

[A]는 내가 쓴 부분, [B]는 마이크로비트와 통신하는 약속이에요. [B]는 고치지 않고 그대로 보내야 웹앱이 장치와 연결돼요.

        보충학습: 등불을 켜는 도우미들의 대화
        

        영어 코드가 길어서 어려웠나요? 먼저 학교 앞 어두운 길에 등불을 켜는 이야기로 알아봐요. 코드를 외울 필요는 없어요.
        

        오늘의 목표는 딱 하나! “누가 살펴보고, 누가 판단하고, 누가 움직이는지” 설명해 보는 거예요.
        

        

        

        1. 등불 팀에는 어떤 친구들이 있을까요?
        

          

        1. 마이크로비트 = 현장 도우미
          주변이 밝은지, 물체가 가까운지 살펴보고 숫자로 알려줘요. 돌아온 지시도 실행해요.
          2. 

        2. 웹앱 = 판단 담당자
          전달받은 숫자를 보고 우리가 정해 둔 규칙에 따라 무엇을 할지 정해요.
          3. 

        3. USB = 쪽지가 오가는 길
          마이크로비트와 컴퓨터 사이에서 숫자와 지시가 오갈 수 있게 해요.
          4. 

        4. 서보·LED = 움직이고 빛나는 도구
          서보모터는 덮개를 움직이고, 네오픽셀 LED는 빛을 내요.
          5. 

        

        공통 코드는 현장 도우미가 들고 있는 업무 안내서예요. “주변 상태를 알려줘. 지시가 오면 그 지시대로 움직여.”라는 내용이 들어 있어요.
        

        이 수업에서는 판단 규칙을 웹앱에 넣어 두었어요. 마이크로비트가 원래 판단을 못한다는 뜻은 아니에요. 우리 작품에서 역할을 이렇게 나눈 거예요.
        

        

        

        2. 어두워졌을 때의 대화를 들어 봐요
        

        우리가 웹앱에 “밝기가 50보다 작으면 덮개를 열자”라는 규칙을 정했다고 생각해 봐요.
        

        ① 마이크로비트: “지금 측정한 밝기 숫자는 30이야!”
        

        ② 웹앱: “30은 50보다 작네. 우리 규칙대로 덮개를 열자. 서보를 90도로 움직여 줘!”
        

        ③ 마이크로비트: “알겠어. 서보에 90도로 움직이라고 전달할게.”
        

        그러면 서보모터가 움직여 덮개가 열려요. LED를 켜려면 웹앱이 LED에 대한 지시도 따로 보내야 합니다.
        

        생각해 보기: “밝기가 50보다 작을 때”를 “80보다 작을 때”로 바꾸고 싶다면 누구의 규칙을 고쳐야 할까요?
        

        생각한 뒤 정답 보기
        웹앱의 규칙을 고치면 돼요. 현장 도우미인 마이크로비트는 계속 밝기 숫자를 알려주면 됩니다.
        

        

        

        3. 시작할 때는 책상을 정리해요
        

        미술 시간에 색연필을 꺼내고 준비물을 확인하듯, 코드도 처음에 준비를 해요.
        

        • “오늘 사용할 LED는 6개야.”
        • “LED마다 어떤 색을 쓸지 기억할 칸 6개를 만들자.”
        • “처음에는 LED를 꺼 두자.”
        • “USB로 컴퓨터와 대화할 준비를 하자.”
        

        이름표가 붙은 보관함을 코드에서는 변수라고 불러요. 보관함이 여러 칸으로 나란히 있는 것은 배열이라고 생각하면 돼요.
        

        궁금하면: 실제 코드 두 줄만 보기
        let PIXEL_COUNT = 6
let pixelColors = [0, 0, 0, 0, 0, 0]
        첫 줄은 “LED 개수라는 보관함에 6을 넣기”, 둘째 줄은 “LED 색을 기억할 여섯 칸 만들기”예요. 여기서 각 칸의 0은 꺼진 색을 뜻해요.
        

        

        

        4. 상태를 적은 쪽지는 ‘칸이 정해진 활동지’예요
        

        활동지에 학년·반·번호를 정해진 순서로 쓰듯, 마이크로비트도 정해진 순서로 숫자를 보내요. 칸과 칸은 쉼표로 구분합니다.
        

        D,거리,흔들림,밝기,온도,A버튼,B버튼,앞뒤기울기,좌우기울기
D,25,80,30,24,0,1,10,-5
        

        지금은 전부 읽으려 하지 말고 거리와 밝기 두 칸만 찾아봐요.
        

        • D 다음 첫 번째 값 25: “물체까지 약 25cm야.”
        • 세 번째 값 30: “밝기 숫자는 30이야.”
        

        순서를 바꾸면 웹앱이 다른 뜻으로 읽을 수 있어요. 활동지의 ‘반’ 칸에 ‘번호’를 쓰면 헷갈리는 것과 같아요!
        

        거리 칸의 −1은 ‘잘 못 재겠어’라는 표시예요. 시험에서 빈칸과 0점이 다르듯, 측정 실패를 “아주 가까워!”라고 해석하면 안 돼요.
        

        궁금하면: 나머지 칸도 읽어 보기
        예시의 흔들림은 80, 온도는 24℃예요. A버튼의 0은 안 누름, B버튼의 1은 누름이에요. 앞뒤 기울기는 10도, 좌우 기울기는 −5도입니다.
        밝기는 0~255 사이의 숫자로 나타내요. 흔들림은 움직임을 알아보기 위한 간단한 숫자이고, 이동 거리는 아니에요. 온도는 보드가 측정하므로 실제 주변 기온과 차이가 날 수 있어요.
        

        

        

        5. 돌아오는 지시는 ‘짧은 주문서’예요
        

        식당에서 “김밥 2줄 주세요!”라고 주문하듯, 웹앱은 무엇을, 얼마나 할지 짧게 보냅니다. 마이크로비트와 미리 약속한 글자를 써요.
        

        주문서우리말로 읽으면
        

        S,90“서보모터를 90도로 움직여 줘!”
        

        L,255,0,0“LED 6개를 모두 빨강으로 켜 줘!”
        

        L,0,0,0“LED를 모두 꺼 줘!”
        

        

        색 숫자 3개는 빨간 조명·초록 조명·파란 조명의 밝기 손잡이라고 생각해요. 255,0,0은 빨강만 세게 켜고 나머지는 끄라는 뜻이에요. 물감을 섞는 것과는 달라요.
        

        더 해보고 싶다면: 다른 주문서 네 가지

        • P,2,0,0,255: 세 번째 LED만 파랑으로! LED 번호는 0, 1, 2, 3, 4, 5라서 2번이 세 번째예요.
        • B,80: LED가 빛나는 전체 밝기를 80으로! 주변 밝기를 재는 센서값과는 달라요.
        • R: LED 6개를 무지개색으로!
        • T: 마지막 LED의 색을 맨 앞으로 옮겨! 여러 번 보내면 색이 한 칸씩 돌아가요.
        

        T는 줄 서 있던 마지막 친구가 맨 앞으로 오는 모습과 비슷해요.
        빨강·주황·노랑·초록·파랑·보라 → 보라·빨강·주황·노랑·초록·파랑
        

        

        

        

        6. 주문을 끝까지 듣고, 계속 살펴봐요
        

        “서보를…”까지만 듣고 움직이면 곤란하겠죠? USB 글자도 나뉘어 도착할 수 있어서, 코드는 한 줄이 끝날 때까지 모아 두었다가 실행해요.
        

        먼저 S,가 도착 → “아직 숫자가 없네. 기다리자.”
        나중에 90과 줄바꿈이 도착 → “90도로 움직이라는 주문이 끝났구나!”
        

        줄바꿈은 ‘주문 끝!’ 표시예요. 코드에서는 \n으로 나타냅니다.
        

        현장 도우미는 이 일을 한 번만 하고 끝내지 않아요. “새 주문 왔나? 주변 상태도 알려주자. 잠깐 쉬고 다시!”를 계속 반복합니다.
        

        궁금하면: 코드 속 이름과 연결해 보기
        여러 일을 묶어 이름을 붙여 두면, 그 이름만 불러서 시킬 수 있어요. 이런 묶음을 함수라고 해요.
        

        • readCommands() = “도착한 주문서를 모아 읽어 줘.”
        • runCommand() = “완성된 주문대로 실행해 줘.”
        • sendSensors() = “지금 주변 상태를 알려줘.”
        • renderPixels() = “기억해 둔 색을 LED에 보여 줘.”
        

        마지막의 basic.forever는 “계속 반복해!”라는 뜻이에요. 이 코드는 주문을 자주 확인하고, 주변 상태는 약 0.2초 간격으로 보내도록 만들었어요.
        

        

        

        7. 친구에게 설명할 수 있는지 확인해요
        

        ① “어두우면 덮개를 열자”는 누가 판단하나요?
        웹앱! 현장 도우미가 숫자를 알려주면 판단 담당자가 우리가 정해 둔 규칙을 확인해요.
        

        ② S,90이라는 주문서를 받으면 무엇을 하나요?
        서보모터를 90도로 움직여요. LED를 켜는 지시는 따로 필요해요.
        

        ③ 주문서가 S,까지만 도착하면 바로 움직일까요?
        기다려요. 숫자와 ‘주문 끝’ 표시인 줄바꿈까지 받아야 해요.
        

        ④ 거리 −1은 ‘물체가 바로 앞에 있다’는 뜻인가요?
        아니요. 잘 측정하지 못했다는 뜻이에요. ‘답을 못 적은 칸’을 거리 숫자로 오해하지 않아야 해요.
        

        30초 설명 도전
        

        “마이크로비트는 현장 도우미처럼 주변을 살펴봐.
        웹앱은 그 숫자를 보고 우리가 정한 규칙대로 판단해.
        USB로 지시를 보내면 마이크로비트가 서보나 LED를 움직여!”
        

        이제 내 작품으로 바꿔 말해 봐요.
        “___ 센서가 ___을 알려주면, 웹앱이 ___라고 판단해서, ___하라는 지시를 보내요.”
        

        오늘은 “살펴보기 → 판단하기 → 지시하기 → 움직이기”만 기억해도 충분해요.
        

        

        

        더 궁금한 친구만 펼쳐 보기
        

        USB는 어디에 꽂고, 무엇을 확인하나요?
        PC의 데이터용 5핀 USB는 마이크로비트 위쪽에 꽂아요. 확장보드 USB는 충전용이에요. 코드를 넣은 뒤 MakeCode 탭을 닫거나 연결을 해제하고 웹앱에서 연결합니다.
        이 수업에서는 robotbit 확장에 포함된 네오픽셀 기능을 써요. neopixel을 별도로 중복 추가하지 않습니다. 처음 뜨는 체크 그림은 코드가 시작했다는 표시이지, 모든 배선을 검사했다는 뜻은 아니에요.
        

        숫자를 잘못 보내거나 너무 크게 보내면요?
        놀이기구에 키 제한이 있듯, 코드도 숫자의 범위를 확인해요. 서보는 0~180도만 받아서 S,200은 실행하지 않습니다. 색과 밝기는 clampNumber()로 0~255 안에 맞춥니다. 이 함수에서는 숫자로 읽히지 않는 값도 최솟값으로 처리해요.
        

        초음파는 어떻게 거리를 재나요?
        벽에 소리치면 메아리가 돌아오듯, 초음파센서는 사람이 듣기 어려운 소리를 보내고 돌아오는 시간을 이용해요. 이 코드는 P14로 출발 신호를 주고 P13으로 들어온 신호의 시간을 읽어 거리로 바꿉니다. 반응이 없거나 2~400cm 범위를 벗어나면 −1로 표시해요.
        

        실제 공통 코드 전체 보기
        영어를 전부 읽지 않아도 괜찮아요. 위에서 배운 readCommands, runCommand, sendSensors 이름부터 찾아보세요.
        공통 메이크코드 버전 5(2026-10-19) 기준입니다. 아래 코드는 사이트 원본에서 가져온 읽기 자료이며, 이 페이지에서 실제 장치로 명령을 보내지는 않습니다.
        // 기본 HTML 없이 쓰는 공통 메이크코드 (버전 5, 2026-10-19: 반복문을 함수 뒤로 옮김, 초음파를 sonar 확장 방식으로 맞춤)
// 사용 전 꼭: 다운로드한 뒤 MakeCode 탭을 닫거나 '연결 해제'하세요.
//   MakeCode가 연결된 채로 있으면 시리얼 데이터를 같이 가져가서 웹앱에 글자가 빠진 채 도착합니다.
// 확장: robotbit (KittenBot) 하나만 추가하세요. neopixel은 robotbit에 들어 있습니다.
//   neopixel을 따로 추가하면 "호환되지 않습니다" 창이 뜹니다. (2026-10-16 메이크코드에서 확인)
// 서보 S1 / 외장 네오픽셀 P15 (6개) / 초음파 Trig P14, Echo P13
// 이 코드는 센서값을 보내고, 받은 명령대로만 움직입니다. 작동 조건은 웹앱이 판단합니다.
//
// 장치 → 웹 (0.2초마다)
//   D,거리,흔들림,밝기,온도,A버튼,B버튼,앞뒤기울기,좌우기울기
//   거리 cm(-1 = 측정 실패) / 흔들림 mg / 밝기 0~255 / 온도 ℃
//   버튼 0·1 / 앞뒤기울기·좌우기울기 도(-180~180)
// 웹 → 장치
//   S,각도            서보 S1 (0~180)
//   L,빨강,초록,파랑    네오픽셀 전체 한 색 (각 0~255, L,0,0,0 = 끄기)
//   P,번호,빨강,초록,파랑  네오픽셀 한 개 (번호 0~5)
//   B,밝기            네오픽셀 밝기 (0~255)
//   R                 무지개색
//   T                 색을 한 칸씩 옆으로 돌리기 (반복해서 보내면 움직이는 효과)
let PIXEL_COUNT = 6
let strip = neopixel.create(DigitalPin.P15, PIXEL_COUNT, NeoPixelMode.RGB)
// 블록 변환 후에도 사라지지 않도록 배열을 값 6개로 바로 만듭니다.
let pixelColors = [0, 0, 0, 0, 0, 0]
strip.setBrightness(40)
strip.clear()
strip.show()
serial.redirectToUSB()
serial.setBaudRate(BaudRate.BaudRate115200)
// 버퍼 크기는 기본값을 씁니다. (setTxBufferSize를 넣었을 때 깨짐이 늘었던 측정이 있어 넣지 않습니다.)
function clampNumber(value: number, low: number, high: number) {
    if (!(value >= low)) return low
    if (value > high) return high
    return value
}
// 밝기는 색을 칠할 때 적용되므로, 저장해 둔 색으로 매번 다시 칠합니다.
function renderPixels() {
    for (let i = 0; i < PIXEL_COUNT; i++) {
        strip.setPixelColor(i, pixelColors[i])
    }
    strip.show()
}
function toColor(red: string, green: string, blue: string) {
    return neopixel.rgb(
        clampNumber(parseInt(red), 0, 255),
        clampNumber(parseInt(green), 0, 255),
        clampNumber(parseInt(blue), 0, 255))
}
// 명령 받기 이벤트(serial.onDataReceived) 대신, 반복문에서 받은 글자를 직접 꺼내 와
// 줄바꿈 단위로 명령을 실행합니다. 이 방식으로 실물 검증을 마쳤습니다.
let receivedText = ""
function readCommands() {
    receivedText = receivedText + serial.readString()
    let newline = receivedText.indexOf("\n")
    while (newline >= 0) {
        runCommand(receivedText.substr(0, newline))
        receivedText = receivedText.substr(newline + 1, receivedText.length)
        newline = receivedText.indexOf("\n")
    }
    // 줄바꿈 없이 너무 길어지면 잘못 들어온 글자로 보고 버립니다.
    if (receivedText.length > 100) {
        receivedText = ""
    }
}
function runCommand(line: string) {
    let fields = line.split(",")
    let command = fields[0].charAt(0)
    if (command == "S" && fields.length == 2) {
        let target = parseInt(fields[1])
        if (target >= 0 && target <= 180) {
            robotbit.Servo(robotbit.Servos.S1, target)
        }
    } else if (command == "L" && fields.length == 4) {
        let color = toColor(fields[1], fields[2], fields[3])
        for (let i = 0; i < PIXEL_COUNT; i++) {
            pixelColors[i] = color
        }
        renderPixels()
    } else if (command == "P" && fields.length == 5) {
        let index = parseInt(fields[1])
        if (index >= 0 && index < PIXEL_COUNT) {
            pixelColors[index] = toColor(fields[2], fields[3], fields[4])
            renderPixels()
        }
    } else if (command == "B" && fields.length == 2) {
        strip.setBrightness(clampNumber(parseInt(fields[1]), 0, 255))
        renderPixels()
    } else if (command == "R") {
        for (let i = 0; i < PIXEL_COUNT; i++) {
            pixelColors[i] = neopixel.hsl(i * 360 / PIXEL_COUNT, 100, 50)
        }
        renderPixels()
    } else if (command == "T") {
        let last = pixelColors.pop()
        pixelColors.unshift(last)
        renderPixels()
    }
}
function sendSensors() {
    // 초음파: sonar 확장(sonar.ping)과 같은 순서로 잽니다. (2026-10-19 실물에서 sonar 방식만 거리가 나와 맞춤)
    pins.setPull(DigitalPin.P14, PinPullMode.PullNone)
    pins.digitalWritePin(DigitalPin.P14, 0)
    control.waitMicros(2)
    pins.digitalWritePin(DigitalPin.P14, 1)
    control.waitMicros(10)
    pins.digitalWritePin(DigitalPin.P14, 0)
    let pulse = pins.pulseIn(DigitalPin.P13, PulseValue.High, 500 * 58)
    let cm = Math.round(pulse / 58)
    let distance = pulse > 0 && cm >= 2 && cm <= 400 ? cm : -1
    let ax = input.acceleration(Dimension.X)
    let ay = input.acceleration(Dimension.Y)
    let az = input.acceleration(Dimension.Z)
    let motion = Math.round(Math.abs(Math.sqrt(ax * ax + ay * ay + az * az) - 1024))
    let brightness = input.lightLevel()
    let temperature = input.temperature()
    let buttonA = input.buttonIsPressed(Button.A) ? 1 : 0
    let buttonB = input.buttonIsPressed(Button.B) ? 1 : 0
    let pitch = input.rotation(Rotation.Pitch)
    let roll = input.rotation(Rotation.Roll)
    serial.writeLine("D," + distance + "," + motion + "," + brightness + "," + temperature + "," + buttonA + "," + buttonB + "," + pitch + "," + roll)
}
// 명령은 0.02초마다 확인하고, 센서 데이터는 0.2초마다 보냅니다.
// 받는 곳의 기본 크기가 작아서, 명령을 자주 꺼내 와야 넘치지 않습니다.
let lastSend = 0
basic.forever(function () {
    readCommands()
    if (input.runningTime() - lastSend >= 200) {
        lastSend = input.runningTime()
        sendSensors()
    }
    basic.pause(20)
})
basic.showIcon(IconNames.Yes)
