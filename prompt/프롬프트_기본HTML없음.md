# 기본 HTML 없이 쓰는 제미나이 프롬프트 (공통 메이크코드 버전 5용)

학생은 **[A] 내 발명품**만 직접 쓰고, **[B] 제작 규칙**은 선생님이 준 문장을 그대로 붙여넣습니다.
마이크로비트에는 선생님이 준 `공통-makecode.ts`(버전 5)가 미리 들어 있어야 합니다.
웹앱을 연결하기 전에 **MakeCode 탭을 닫거나 연결 해제**해야 합니다. 열려 있으면 데이터 글자가 빠집니다.

## [B] 제작 규칙 — 그대로 붙여넣기

[실행 환경]
- Windows 노트북의 크롬(Chrome) 브라우저에서 HTML 파일 하나로 실행한다.
- HTML·CSS·JavaScript를 한 파일에 넣고, 외부 라이브러리·폰트·이미지는 쓰지 않는다.
- 마이크로비트 코드는 이미 준비되어 있으니 만들지 말고, 아래 통신 규칙만 지킨다.

[통신 규칙 — 바꾸지 말 것]
- Web Serial API, 통신 속도 115200, 메시지 끝은 줄바꿈 "\n".
- 마이크로비트 → 웹 (0.2초마다), 쉼표로 나뉜 숫자 8개:
  D,거리,흔들림,밝기,온도,A버튼,B버튼,앞뒤기울기,좌우기울기
  - 거리: cm 정수. -1은 측정 실패이므로 조건 판단에 쓰지 않는다.
  - 흔들림: mg 정수 (1000 = 1g). 가만히 두면 0 근처.
  - 밝기: 0(어두움)~255(밝음).
  - 온도: ℃ 정수.
  - A버튼, B버튼: 누르고 있으면 1, 아니면 0.
  - 앞뒤기울기: -180~180도. 화면이 위를 보고 평평하면 0. 앞뒤로 숙이는 방향에 따라 + 또는 −.
  - 좌우기울기: -180~180도. 평평하면 0. 좌우로 기울이는 방향에 따라 + 또는 −.
  - 기울기 방향은 20도 이상일 때만 '앞/뒤/왼쪽/오른쪽'으로 판단하고, 그 밖에는 '평평'으로 본다. 앞뒤 부호는 실제 장치로 확인할 수 있게 화면에 숫자도 함께 보여준다.
- 웹 → 마이크로비트:
  - S,각도 : 서보모터 S1 (0~180 정수)
  - L,빨강,초록,파랑 : 네오픽셀 6개 전체를 한 색으로 (각 0~255). 끄기는 L,0,0,0
  - P,번호,빨강,초록,파랑 : 네오픽셀 하나만 (번호 0~5)
  - B,밝기 : 네오픽셀 밝기 (0~255, 기본 40). 눈부심을 막기 위해 120 이하를 권장한다.
  - R : 6개를 무지개색으로
  - T : 지금 색을 한 칸씩 옆으로 돌리기. 0.2초 이상 간격으로 반복해서 보내면 움직이는 효과가 된다.
- 마이크로비트는 응답(ACK)을 보내지 않는다. 응답을 기다리지 않는다.
- 명령은 0.05초 이상 간격을 두고 보낸다. 여러 개의 P 명령도 순서대로 하나씩 보낸다.

[화면 연출 — 가장 중요, 내 발명품만의 화면]
- 흰 카드만 늘어놓은 평범한 설정 화면으로 만들지 않는다. 처음 보는 사람이 "무슨 발명품인지" 그림만 보고 알 수 있게 한다.
- 맨 위 머리: 아이콘, ⑧의 작품 이름(영어 이름과 버전도 좋다. 예: GeoRoot Guard v1.0), 한 줄 소개, 오른쪽에 지금 상태 배지(예: 모니터링 중 / 경고 / 체험 중).
- 그 아래에 화면에서 가장 큰 '상황 장면'을 canvas나 SVG로 직접 그린다. ②의 장치가 실제로 쓰이는 곳(⑧의 장소: 예 땅속 단면, 밤 골목길, 레이더 화면, 교실 책상 위)을 배경으로 그리고 장치를 그 안에 둔다. 이모지 한 개로 장면을 대신하지 않는다.
- 센서값이 바뀌면 장면 속 사물이 직접 움직인다. 숫자만 바꾸지 말고 그림으로 보여준다. (예: 흔들림 → 땅과 흙 알갱이가 흔들림, 거리 → 레이더 점이 다가옴, 밝기 → 하늘이 어두워지고 별이 뜸, 기울기 → 장치 그림이 기울어짐)
- ④를 만족하면 장면 전체가 경고 연출로 바뀐다(색, 빛, 깜빡임, 큰 문구, 경고 소리는 버튼을 눌러 켠 뒤에만). ⑦이 되면 차분한 모습으로 돌아온다.
- 장면 바로 아래에 '상황 버튼' 3~4개를 둔다. ④를 만족하는 상황과 만족하지 않는 상황을 하나 이상씩 넣고, 버튼에 상황 이름과 값을 적는다. (예: "승용차 접근 · 420cm / 35km/h (위험)", "작은 야구공 · 15cm (안전)") 누르면 화면 체험 모드의 센서값이 그 상황으로 바뀐다. '초기화' 버튼도 둔다.
- '조건 확인' 판: ④를 조건 한 줄씩 나눠 지금 값과 '조건 충족 / 미충족'을 표시한다.
- ⑧의 색과 분위기로 배경, 판, 글자, 강조색을 한 가지 테마로 통일한다. 판에는 둥근 모서리와 은은한 테두리나 빛을 쓴다.
- 움직임은 requestAnimationFrame으로 부드럽게 그리고, 화면이 멈춰 보이지 않게 배경에도 작은 움직임(흐르는 입자, 레이더 선 회전 등)을 넣는다.

[센서 확인판 — 장면 아래에]
- 센서값 8개를 작은 카드로 모두 보여준다. 각 카드에 이름, 숫자, 단위, 값에 따라 길이가 변하는 막대를 넣는다. ③에서 고른 센서는 크게, 나머지는 작게 보여준다.
- 버튼은 눌리면 카드 색이 바뀌고, 기울기는 방향을 화살표로 보여준다.
- 흔들림과 거리는 최근 10초 변화를 작은 그래프로 그린다 (canvas 사용).
- 네오픽셀 6개를 동그라미 6개로 그리고, 보낸 명령(L, P, B, R, T)대로 색이 똑같이 바뀌게 한다. 장면 속 장치에도 같은 불빛을 보여주면 더 좋다.
- '통신 기록'은 접고 펼 수 있는 칸에 두고, 받은 줄과 보낸 명령을 최근 15개만 시간과 함께 보여준다.
- 센서값이 내 작동 조건에 가까워지면 카드에 강조 표시를 한다.

[연결 처리]
- 'USB 연결' 버튼의 클릭 처리 함수 안에서 navigator.serial.requestPort()를 호출한다.
- navigator.serial이 없으면 "Edge 또는 Chrome에서 열어주세요"를 화면에 표시한다.
- 받은 데이터는 TextDecoder로 바꿔 버퍼에 모으고, "\n"이 올 때마다 한 줄씩 처리한다. 줄 끝의 "\r"은 지운다.
- D로 시작하고 숫자가 정확히 8개인 줄만 사용하고, 나머지는 무시한다.
- 첫 D 데이터를 받았을 때 '연결 완료'를 표시한다. 포트만 열린 상태는 '데이터 기다리는 중'으로 표시한다.
- 2초 넘게 D 데이터가 없으면 '데이터 끊김'을 표시하고, 오래된 값은 흐리게 보여준다.
- 보내기는 TextEncoder로 하고, 보내는 중에 다시 보내지 않도록 대기열로 순서대로 보낸다.
- '연결 해제' 버튼을 만들고, 해제 후 다시 연결할 수 있게 한다. 해제할 때 L,0,0,0을 먼저 보낸다.
- 연결 실패, 연결 취소, 포트 사용 중 같은 오류는 이유를 화면에 한국어로 보여준다.
- 연결 버튼 근처에 "연결 전에 MakeCode 탭을 닫으세요" 안내를 항상 보여준다. 포트 사용 중 오류가 나거나 숫자 8개가 아닌 줄이 자주 들어오면 이 안내를 강조한다.

[두 가지 모드]
- 화면 체험 모드: USB 없이 바로 작동한다. 처음 열면 이 모드로 시작한다. 상황 버튼과, 센서 8개를 흉내 내는 슬라이더·체크박스('직접 조절' 칸)로 값을 바꾼다. 장치에는 아무것도 보내지 않고, 장면·확인판·네오픽셀 그림은 실제와 똑같이 움직인다.
- 실제 장치 모드: 마이크로비트가 보낸 값만 쓴다. 가짜 값을 만들지 않는다.
- 두 모드 모두 같은 판단 함수로 ④와 ⑦을 처리한다.

[작동 판단]
- 상태가 바뀔 때만 명령을 보낸다. 같은 상태가 이어지면 같은 명령을 반복하지 않는다. (T 반복 애니메이션은 예외)
- 켜지는 기준과 꺼지는 기준을 다르게 두어(예: 15cm에서 켜고 25cm에서 끔) 경계에서 깜빡이지 않게 한다.
- 화면에서 서보 각도, 네오픽셀 전체 색(색 선택기), 개별 LED 색, 밝기, 무지개, 회전을 직접 바꿔보는 '장치 조작판'도 만든다. 접고 펼 수 있는 칸에 둔다.

[버튼 오류 방지]
- onclick 속성을 쓰지 말고, 스크립트를 body 맨 끝에 두고 addEventListener로 연결한다.
- type="module"을 쓰지 않는다.
- 모든 버튼의 id와 스크립트의 id가 같아야 하고, 호출하는 함수는 모두 실제로 만들어져 있어야 한다.
- 빈 함수, "여기에 코드 추가", 생략 표시(...)를 넣지 않는다.

[결과물]
- 생략 없는 완전한 HTML 코드 한 개를 준다.
- 화면 글자와 설명은 모두 한국어로 쓴다.
- 코드 아래에 화면 체험에서 시험해 본 순서를 3줄로 적고, 실제 장치로 시험하지 못한 것은 '미확인'이라고 적는다.

## 작성 예시 ([A] 부분)

① 해결할 문제: 밤에 어두운 골목길을 걸을 때 무섭고 발밑이 잘 안 보인다.
② 장치 모양: 가방에 다는 작은 등불, 덮개가 서보모터로 열림
③ 사용할 센서: 밝기, 흔들림, A 버튼
④ 작동 조건: 밝기가 50보다 어두워지면 덮개를 열고, 걷느라 흔들리면 불빛을 움직이게 한다. A 버튼을 누르면 빨간색 경고등으로 바뀐다.
⑤ 실제 장치 반응: 서보모터 90도, 네오픽셀 무지개색을 회전, A 버튼을 누르면 6개 모두 빨간색
⑥ 화면 반응: 밤 골목길 장면에서 어두워질수록 하늘에 별이 뜨고, 가방에 단 등불의 덮개가 열리며 불빛이 퍼진다. 걸어서 흔들리면 등불이 흔들리고 불빛이 길 위를 따라 움직인다. A 버튼을 누르면 화면 테두리가 빨갛게 깜빡이며 "도와주세요!" 문구가 크게 뜬다.
⑦ 원래대로 돌아오는 조건과 상태: 밝기가 80보다 밝아지면 덮개를 닫고(서보 0도) 네오픽셀 끄기
⑧ 디자인: 작품 이름 "NightLamp 등불이 v1.0", 배경은 가로등이 하나 있는 밤 골목길, 남색 밤하늘과 노란 불빛, 아늑한 분위기
