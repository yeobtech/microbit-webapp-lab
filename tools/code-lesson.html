보충학습: 공통 코드는 무슨 일을 할까요?

작품을 만든 뒤 읽는 선택 학습입니다. 모든 줄을 외우기보다 센서값 → 웹앱의 판단 → 명령 → 장치의 동작을 설명할 수 있으면 됩니다.

자료 기준: 공통 메이크코드 버전 5(2026-10-19). 아래 예시는 읽기 연습이며 실제 장치로 명령을 보내지 않습니다.

1. 먼저 역할을 나눠 봐요

  1. ① 마이크로비트
    센서값 측정
  2. ② USB → 웹앱
    조건 판단
  3. ③ USB → 마이크로비트
    명령 읽기
  4. ④ 서보·네오픽셀
    동작 실행

이 코드에는 “어두워지면 덮개 열기” 같은 작품의 판단 규칙이 없습니다. 밝기를 읽어서 보내는 일과 받은 각도로 서보를 움직이는 일을 맡습니다. “얼마나 어두우면 열까?”는 웹앱에서 정합니다.

PC의 데이터용 5핀 USB는 마이크로비트 위쪽 단자에 연결해요. 확장보드 USB는 충전용입니다. 코드를 넣은 뒤에는 MakeCode 탭을 닫거나 연결을 해제하고 웹앱에서 연결하세요.

2. 시작할 때 한 번 준비해요

let PIXEL_COUNT = 6
let strip = neopixel.create(DigitalPin.P15, PIXEL_COUNT, NeoPixelMode.RGB)
let pixelColors = [0, 0, 0, 0, 0, 0]
strip.setBrightness(40)
strip.clear()
strip.show()
serial.redirectToUSB()
serial.setBaudRate(BaudRate.BaudRate115200)
  • PIXEL_COUNT: LED가 몇 개인지 저장하는 변수예요. 이 작품에서는 6개입니다.
  • strip: P15에 연결된 네오픽셀을 제어하는 대상입니다. pixelColors 배열은 LED 6개의 색을 기억하는 칸이에요.
  • 밝기를 40으로 설정하고 저장된 출력을 지운 뒤 show()로 꺼진 상태를 반영합니다.
  • serial: USB로 글자를 주고받을 준비입니다. 웹앱의 통신 속도도 115200으로 맞춥니다.

수업의 확장은 robotbit을 사용합니다. 이 프로젝트에서는 robotbit에 포함된 neopixel 기능을 쓰므로 별도로 중복 추가하지 않습니다.

3. 반복하면서 받고, 때가 되면 보내요

basic.forever(function () {
    readCommands()
    if (input.runningTime() - lastSend >= 200) {
        lastSend = input.runningTime()
        sendSensors()
    }
    basic.pause(20)
})
  1. readCommands()로 웹앱에서 온 글자를 꺼내 읽어요.
  2. 마지막 전송 시각인 lastSend에서 200ms 이상 지났으면 sendSensors()를 실행해요.
  3. 20ms 쉬고 다시 반복합니다. 1000ms는 1초예요.

명령은 자주 확인하고 센서값은 약 0.2초 간격으로 보내려는 구조입니다. 센서 측정과 명령 실행에도 시간이 걸리므로 정확히 20ms·200ms마다 실행되는 타이머는 아닙니다.

basic.showIcon(IconNames.Yes)의 체크 표시는 코드 시작을 알리는 표시예요. USB 통신과 모든 배선이 정상이라는 검사 결과는 아닙니다.

4. 센서값 한 줄을 해석해요

sendSensors()가 읽은 값을 쉼표로 이어 serial.writeLine()으로 보내요. 맨 앞의 D는 데이터라는 표식이고, 뒤에는 값 8개가 옵니다.

D,거리,흔들림,밝기,온도,A,B,앞뒤기울기,좌우기울기
D,25,80,30,24,0,1,10,-5

예시를 읽으면 “거리 25cm, 흔들림 지표 80mg, 밝기 30, 온도 24℃, A는 안 누름, B는 누름, 앞뒤 10도, 좌우 −5도”입니다.

거리·흔들림 숫자는 어떻게 만들까요?

초음파 거리: P14(Trig)에 짧은 신호를 주고 P13(Echo)의 HIGH 지속 시간을 pulseIn()으로 잽니다. 그 시간을 58로 나누고 반올림해 cm로 환산합니다. 응답이 없거나 이 코드의 인정 범위인 2~400cm를 벗어나면 -1을 보냅니다.

흔들림 지표: X·Y·Z 가속도의 크기를 구한 뒤 중력 기준값 1024와의 차이에 절댓값을 취합니다. 가만히 두었을 때 대체로 작고 움직일 때 커지는 간단한 지표이며, 이동 거리나 모든 움직임을 정확히 나타내는 값은 아닙니다.

밝기와 온도: 밝기는 0~255 범위의 값이며 lux 단위가 아닙니다. 온도는 보드 내부 센서값이므로 주변 기온과 차이가 날 수 있어요.

distance = -1은 “아주 가까움”이 아니라 측정 실패입니다. 웹앱에서 “20cm 미만”을 검사할 때에는 먼저 유효한 거리인지 확인해야 해요.

5. 웹앱의 짧은 명령을 동작으로 바꿔요

runCommand()는 한 줄을 쉼표로 나눠 명령과 숫자를 읽습니다. 아래 명령들은 실제로 보낼 때 끝에 줄바꿈(\n)이 필요합니다.

명령 예시실행하는 일읽을 때 주의할 점
S,90S1 서보를 90도로 설정각도는 0~180. S1은 P1과 달라요.
L,255,0,0LED 6개를 모두 빨강으로빨강·초록·파랑 순서. 0,0,0은 꺼짐.
P,2,0,0,255세 번째 LED만 파랑으로번호는 0부터 시작해서 0~5예요.
B,80출력 밝기를 80으로 변경범위 0~255. 센서 밝기와는 다른 값입니다.
R6개에 무지개색 배치이 명령 한 번으로 계속 회전하지는 않아요.
T마지막 색을 맨 앞으로 이동반복해서 보내면 색이 한 칸씩 돌아갑니다.
왜 색을 배열에 기억하고 다시 칠할까요?

pixelColors는 원래 색을 기억합니다. renderPixels()는 6개를 반복하며 setPixelColor()로 칠한 뒤 show()로 반영합니다. 밝기를 바꿔도 저장한 색으로 다시 칠할 수 있어요.

T는 pop()으로 마지막 색을 꺼내 unshift()로 맨 앞에 넣습니다. 예를 들어 [빨강, 주황, 노랑, 초록, 파랑, 보라]는 [보라, 빨강, 주황, 노랑, 초록, 파랑]이 됩니다.

숫자가 범위를 벗어나면 어떻게 될까요?

clampNumber()는 RGB와 밝기를 0~255에 맞춥니다. 이 함수에서는 숫자로 해석되지 않는 값도 최솟값으로 처리됩니다. 반면 S,200은 180도로 바뀌는 것이 아니라, 서보 각도 검사에서 걸러져 실행되지 않습니다. LED 번호도 0~5인지 검사합니다.

6. USB 글자가 나뉘어 도착해도 한 줄로 모아요

명령이 반드시 한 번에 도착하는 것은 아닙니다. readCommands()는 받은 글자를 receivedText에 이어 붙이고, 줄바꿈을 찾을 때까지 기다립니다.

첫 번째 수신: "S,"
두 번째 수신: "90\n"
모은 한 줄:   "S,90" → runCommand() 실행

한꺼번에 여러 줄이 오면 while 반복문으로 완성된 줄들을 차례로 실행합니다. 마지막에 남은 불완전한 줄은 다음 수신 때 이어 붙입니다. 완성된 줄을 처리한 뒤 남은 글자가 100자를 넘으면 비웁니다.

7. 예측한 뒤 정답을 열어 봐요

① 밝기 30을 받으면 공통 코드가 스스로 S,90을 결정할까요?

아니요. 공통 코드는 밝기 30을 보냅니다. 웹앱이 조건을 판단하고 S,90을 보내야 서보가 움직입니다.

② P,2,0,255,0은 몇 번째 LED를 무슨 색으로 바꿀까요?

세 번째 LED를 초록색으로 바꿉니다. LED 번호는 0부터 세고, RGB의 가운데 값이 초록입니다.

③ S,90을 보냈는데 줄바꿈을 빠뜨리면 바로 실행될까요?

바로 실행되지 않습니다. readCommands()가 줄바꿈을 찾아 한 줄이 완성됐다고 판단해야 실행합니다.

④ 거리 −1을 받았을 때 장애물이 바로 앞에 있다고 판단해도 될까요?

안 됩니다. 이 코드에서 −1은 측정 실패입니다. 유효한 거리인지 먼저 검사해야 합니다.

마지막으로, 친구에게 30초 동안 설명해 봐요

  1. 역할: “마이크로비트는 센서값을 읽고, 웹앱은 그 값으로 판단해.”
  2. 예시: “밝기 30을 보내면 웹앱이 어둡다고 판단해서 S,90을 보낼 수 있어.”
  3. 실행: “공통 코드가 명령을 읽고 S1 서보를 90도로 움직여.”
  4. 확인: “그래서 조건을 바꾸려면 웹앱을 고치고, 핀 번호와 통신 약속은 서로 맞춰야 해.”
